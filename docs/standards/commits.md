# Commits

- **Give every commit one purpose.** A Ninja framework run makes one work commit and one log-only commit (see below). Work done by hand outside the runner is split into small commits. Why: a commit with one purpose is easy to review and easy to undo.
- **Stage files by name with `git add path/to/file`.** Never use `git add -A` or `git add .` without reviewing every change first. Why: it is how a stray file or a secret gets committed.
- **Run `git diff --cached --stat` in the same step as `git commit`.** Check that the files listed are the ones you meant. Why: another session can change the staging area between your `add` and your `commit`.
- **Run `npm test`, `npm run typecheck`, `npm run lint`, `npm run build` and `npm run e2e` before a push.** All five pass. Why: the push is the point where a mistake reaches the member.
- **Write the commit message to say why.** The first line says what changed, in plain words, and the lines after say the reason. Why: the diff already shows what, and only the message can say why.
- **Fix each review finding of work done by hand in its own commit.** Name the finding in the message and add its test in the same commit. A run fixes its review findings inside the run, before its one work commit. Why: a reviewer can then confirm each finding is closed by reading one commit.
- **Never commit `.env.local`, `.data/` or any secret.** Why: a secret in history stays in history (see `security.md`).
- **Give a Ninja framework run one work commit on its run branch, then one log-only commit, and merge it only on the owner's yes.** The run works on the branch `run/<date>-<verb>-<entry with / as ->`, such as `run/2026-10-06-install-routines-booking-reminders`. It runs `npm run key:sync`, makes one work commit with `key/knowledge/system.md` in it, then makes one log-only commit whose entry names the work commit's id (see `log.md`). It goes live only by merging into `main` on the owner's yes. Why: one run is one change the owner can read, accept or drop whole, and nothing reaches `main` without their consent.
- **Keep the same order for work done by hand outside the runner.** Make the work, run `npm run key:sync`, make the work commit, then make the log-only commit naming its id, one small step at a time. Why: a sync run after the commits leaves `system.md` changed with no commit to hold it, and an entry cannot hold the id of the commit that contains it.
