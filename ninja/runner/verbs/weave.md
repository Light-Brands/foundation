# Weave

Weave connects installed entries into one system: events that cross from one entry to another, shared records, routines that span modules, and the Command center dashboard that shows the whole business at once. "Weave Sales and Delivery so a signed contract starts a project" is a weave.

## Phase 1

Weaving is designed in Phase 3 of the Ninja framework, together with the first blueprints. In Phase 1, the runner answers a weave request by running [check](check.md) on the entries named, then explaining what weaving them will make possible.

## What the runner does today

1. **Check.** Run [check](check.md) on the departments or entries the request names: what is installed, whether it is working, and whether it is current.
2. **Explain.** The [guide](../../crew/guide.md) describes what weaving these entries will do once it is available: which events will pass between them, which records they will share, which routines will span them, and what the Command center dashboard will show. Use the owner's own entries and words.
3. **Next moves.** Offer the runs available now that move the business toward the weave: installing an entry the weave needs, or upgrading one to the tier the weave builds on.

## Stages

Stages 1 to 3, as [check](check.md) runs them. Nothing is written.

## Questions

Which entries to connect, and what the owner wants to happen between them, only when the request does not already say it.

## The close

The check's read, the explanation, and the ranked next moves. The receipt says plainly that nothing was changed.
